= Отчет: Работа с прерываниями в микроконтроллерах STM
:author: Залипаева Эвелина КЭ-201

== 1. Прерывания: принцип работы и типы

=== Что такое прерывания?
Прерывания — это механизм, позволяющий микроконтроллеру временно приостановить выполнение основной программы для обработки внешнего или внутреннего события.

=== Типы прерываний:
* *Аппаратные*: Генерируются периферийными устройствами (таймеры, кнопки, UART и т.д.).
* *Программные*: Вызываются специальными инструкциями (например, `SVC` для системных вызовов).
* *Исключения*: Ошибки выполнения (деление на ноль, доступ к недопустимой памяти).

=== Что происходит при прерывании?
1. Процессор сохраняет текущий контекст (регистры) в стек.
2. Переходит к выполнению *обработчика прерывания* (ISR).
3. После завершения ISR восстанавливает контекст и возвращается к основной программе.

== 2. Контроллер прерываний NVIC

=== Что такое NVIC?
*Nested Vectored Interrupt Controller (NVIC)* — встроенный контроллер, управляющий приоритетами и обработкой прерываний в ядрах Cortex-M.

=== Основные функции:
* Установка приоритетов прерываний (0 — высший, чем больше число — тем ниже).
* Разрешение/запрет отдельных прерываний.
* Поддержка вложенных прерываний (прерывание может прервать выполнение другого обработчика).

== 3. Таблица векторов прерываний

=== Определение:
Таблица векторов прерываний — это массив адресов функций-обработчиков, расположенный в начале памяти микроконтроллера.

=== Структура:
* Каждая запись соответствует конкретному прерыванию (например, вектор для TIM2 — адрес обработчика переполнения таймера 2).
* Размер таблицы зависит от модели микроконтроллера (STM32F4 содержит ~100 векторов).

== 4. Обработчик прерываний (ISR)

=== Требования к ISR:
1. *Короткое выполнение*: Не должен блокировать систему надолго.
2. *Очистка флагов*: После обработки необходимо сбросить флаг прерывания (иначе оно сработает повторно).
3. *Безопасность*: Избегать операций, которые могут вызвать дедлоки (например, ожидание в цикле).

=== Пример обработчика для STM32:
[source,c]
----
void TIM2_IRQHandler(void) {
    if (TIM2->SR & TIM_SR_UIF) { // Проверка флага переполнения
        // Логика обработки...
        TIM2->SR &= ~TIM_SR_UIF; // Сброс флага
    }
}
----

== 5. Обработка события по переполнению таймера 2

=== Настройка таймера TIM2:
1. *Включение тактирования TIM2*:
[source,c]
----
RCC->APB1ENR |= RCC_APB1ENR_TIM2EN;
----

2. *Настройка периода переполнения*:
[source,c]
----
TIM2->ARR = 8399; // Переполнение каждые 1 мс (при тактовой частоте 84 МГц)
TIM2->PSC = 0;    // Предделитель = 1
----

3. *Разрешение прерывания по переполнению*:
[source,c]
----
TIM2->DIER |= TIM_DIER_UIE; // Разрешить прерывание
----

4. *Настройка NVIC*:
[source,c]
----
NVIC_SetPriority(TIM2_IRQn, 1); // Приоритет 1
NVIC_EnableIRQ(TIM2_IRQn);       // Разрешить прерывание
----

5. *Запуск таймера*:
[source,c]
----
TIM2->CR1 |= TIM_CR1_CEN; // Включить таймер
----

=== Принцип работы:
1. При достижении счетчиком TIM2 значения в регистре ARR возникает переполнение.
2. Устанавливается флаг `UIF` в регистре `TIM2->SR`.
3. NVIC направляет прерывание в процессор.
4. Выполняется обработчик `TIM2_IRQHandler`.
5. Флаг `UIF` сбрасывается, и таймер продолжает работу.

== Выводы
1. Прерывания позволяют эффективно реагировать на асинхронные события.
2. NVIC управляет приоритетами и вложенностью прерываний.
3. Таблица векторов связывает прерывания с их обработчиками.
4. Корректная обработка прерываний требует очистки флагов и оптимизации кода ISR.
5. Пример с TIM2 демонстрирует настройку прерываний для периферийных устройств.
